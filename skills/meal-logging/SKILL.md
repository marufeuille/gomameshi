# 食事記録スキル（ごまめし）

利用者が食事の写真を送ったとき、または食事内容を言葉で伝えたときに、
ごまめし（食事とPFC）へ記録するための手順。アクション名は `server/src/actions.ts` の
`Actions` 定義が正本。

## Flow

- 写っている料理を品目に分け、グラム推定と一緒に内訳を提示してから記録する。
  量はすべて推定として明示する。写真からの記録では、後述の根拠表を出して
  利用者が誤りに気づける形にする。
- 値が大きく変わる不明点だけを聞く（主な食材・魚種、主食の量、残した分）。
  質問は最大3つまで。
- 利用者本人の量の申告（例:「ご飯は200くらい」）は写真推定より優先する。
- 各品目は記録前に `listFoods` で食品マスタに解決する。検索は名前への部分一致なので、
  ひらがな・漢字・別名の表記ゆれを試す。
- 市販品は成分表示（ラベル）が第一の根拠で、推測は最後の手段。
  - マスタに登録済みの常用品があればそれを使う。
  - 未登録で、利用者が送った写真の栄養成分表示が完全に読める場合は、
    印刷値そのままで `upsertFood` 登録する（source は `label`、ラベルが1個あたりなら
    per-serving 基準）。ラベルに無い栄養素は null のままにする。
  - パッケージは見えるがラベルが読めない場合は、ラベル写真の追加を依頼するのが既定。
    その品目は「ラベル確認待ち」として根拠表に残し、残りの食事だけ先に記録する。
  - ラベルが得られない場合（外食、廃棄済み）だけ、アプリの検索フロー
    （`lookupFoodInfo` / `startDeepFoodResearch`）か、開示つきの推定にフォールバックする。
- 記録は `logMeal` で品目ごとに行う（日付、食事枠、外食なら eatingOut: true）。
  塩分の多い調味料など、塩分合計に効くものは小さくても独立した品目として記録する。
- 複合料理（汁物、煮物など）は `logAssistParts` で一品として記録する：
  標準の構成要素にグラムと根拠を持たせ、だし・水は excluded にする。
- 利用者が「残した」と言った分は除外する。
- 記録後は `getDailySummary` で検証し、記録した品目・その食事の合計・
  その日累計・代替した点（後述）を報告する。根拠表の行を利用者が訂正したら、
  その記録を直して何が変わったかを伝える。

## 根拠表

写真からの記録では、推定品目ごとに1行、料理単位（例: カレー、定食の味噌汁）で出す。

| 推定品目 | 量 | 量の根拠 | 根拠 | ほかの候補 |
|---|---|---|---|---|

- 推定品目： 写真から同定した料理・食品。
- 量： 記録に使うグラム数（または個数・食数）。
- 量の根拠： 本人の申告か写真推定か。量の訂正と食品の訂正を分けられるよう、独立の列にする。
- 根拠： 実際に使ったマスタ食品（登録名と食品番号または id、その基準値 kcal/P/F/C）、
  市販品ならラベル値またはメーカー公式ページの URL。数値の出どころを裸の主張で終わらせない。
- ほかの候補： 本当にありえた別のマスタ食品や推定経路。無理に埋めない。

複合料理は、成分表に料理単位の項目があれば丸ごと1品で記録でき、無ければ構成要素に
分解する。両方の経路がある場合は、使わなかった方を「ほかの候補」に入れておき、
利用者が言えば切り替える。

## Rules

- 栄養値を発明しない。すべての数値は「マスタ食品 × グラム」からアプリ側で計算される。
- 代替は報告で開示する。ぴったりのマスタ食品が無く近い食品で代用したら、その旨を明示する。
- 新規マスタ登録はラベル写真の印刷値から（上記 Flow）。Web 検索での登録は
  アプリ自身の検索フローに任せ、それ以外の不足は推測で埋めず「不足」として残す。
- 例外： アプリの深掘り検索（`startDeepFoodResearch`）が進捗なく約5分止まった場合は、
  メーカー公式の商品ページで値を直接確認し、パッケージ自体の表示（例: 100 kcal あたりの
  たんぱく質量）と突き合わせてから `upsertFood` で登録する（source は `ai`、
  公式ページを出典名/URL にする）。範囲で印刷された値（例: 食物繊維 0〜1.4g）は null のまま。
  停滞とフォールバックは報告で開示する。
- 利用者個人の常用品・目標値・癖はこのスキルに書かない。それらはアプリ側のデータと
  利用者ごとのメモに置く（スキルは一般手順だけを持つ）。
